How a card tap becomes an attendance record
Two related SQLite tables: one row of identity per student, one timestamped row per tap.

1 : N  one student, many taps
Each tap matches the card’s uid to a row in students, then inserts one timestamped row into attendance, linked back by student_id → id. Splitting identity from events keeps student details in one place and lets the same student be logged any number of times.
